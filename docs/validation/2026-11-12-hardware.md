# 硬件支持验证 — 2026-11-12

本次改动让 Debian 镜像接管原厂图形程序负责的硬件工作，并把结果通过 LILYGO 应用
已有的接口提供出来。对照和设置说明见 [硬件支持对照](../hardware-support.md)。

没有接板卡。下面全部是主机、容器和 QEMU 用户态下的检查；扬声器、电量读取、
充电、模组上电、相机等硬件行为都没有在 T-Display-K230 上确认。

## 依据的输入

- 原厂源码 `Xinyuan-LilyGO/T-Display-K230` 提交
  `c27c58c07ca5e39d15f5dcf1b7103aead29282df`（克隆后只读查阅）。
- 原厂 v0.2.9 镜像，即 `.cache/k230-v0.2.9/images/sysimage-sdcard.img`：用
  `debugfs` 只读导出 rootfs 的 `/etc`、boot 分区的设备树并反编译，没有挂载或修改
  镜像。
- 同一镜像另外导入了带相机运行时的 BSP 目录 `.cache/k230-v0.2.9-camera`
  （`scripts/import-bsp.py --include-camera-runtime`），原目录未改动。

从这些输入确认的事实，决定了实现方式：

- 原厂开机脚本加载 `8189fs`、`8723ds`、`aic_load_fw`、`aic8800_fdrv`、`aic_btusb`；
  此前的 `board.conf` 只列了 `8723ds`。
- 内核配置里 `BATTERY_BQ27XXX`、`CHARGER_BQ25890`、`KEYBOARD_TCA8418`、
  `INPUT_DRV260X_HAPTICS`、`INPUT_UINPUT`、`RFKILL`、`RTC_DRV_K230` 均未启用；
  `DEVMEM=y` 且没有 `STRICT_DEVMEM`。
- 设备树把 IO46/IO47 接到独立 `i2c-gpio` 适配器（Linux 动态 `/dev/i2c-*`），没有 `gpio-keys` 节点。
- 内核声卡的控件有 `PCM Playback Volume`、`Codec Route`、
  `External I2S Output Switch`；没有名为 `Master` 的控件。
- 原厂充电默认值是 704 mA、4288 mV，低电量关机阈值 3600 mV（三次、间隔 30 s）。

## 改动

共享板级目录 `lilygo-linux-dtoverlays/boards/T-Display-K230`：

- `lilygo-k230-audio`：softvol 的 `Master Playback Volume` 控件及其创建；
  `/run/lilygo-k230-audio/control` 套接字和 `lilygo-k230-audio-route` 命令。
- 新增 `lilygo-k230-peripherals`（IO2、IO44）和 `lilygo-k230-power`（BQ27220、
  BQ25896、低电量关机、`/run/lilygo-k230/power_supply`）。
- 新增 udev 规则、`.link`、logind、NetworkManager 配置和交给应用的环境文件。
- `profile.json` 增加 `kernel` 段，`runtime` 增加 `services` 和 `build`。

`canaan-gen`：

- `stage2` 按 profile 启用服务、在镜像内编译 `libk230mmio.so`；原来放在 `stage2`
  的 udev 规则并入共享目录；相机运行时增加 `sched_rt_runtime_us` 设置。
- `board.conf` 加载原厂同样的模块；`stage1` 建立 `gpio` 组并安装 `i2c-tools`。
- 预检核对板级运行时需要的内核选项，列出内核没有提供的可选功能。
- `check-ui-rootfs.py` 只接受共享目录提供的 Launcher 环境 drop-in。

## 已完成的检查

- **单元测试**（Homebrew Python 3.14）：`canaan-gen` 151 项、板级运行时 79 项、
  SDK 部署 10 项全部通过。系统自带的 Python 3.9 有 4 项既有测试因主机差异报错
  （`Path.hardlink_to`、`os.major`），与本次改动无关。
- **板级测试的内容**：电源服务在模拟的开漏 SCL/SDA 和寄存器从设备上逐位运行，
  核对起始/停止、应答、读写数据，以及引脚功能在成功、无应答、线被占用、时钟被
  拉低四种情况下都恢复为 GPIO-I2C；核对充电寄存器的写入值（0x07→0x8D、0x04→0x0B、
  0x06→0x72）、不相关位保持、低电量规则和发布目录。人为改错位序、应答、移位、
  计数、引脚恢复这五处，测试都能发现。
- **Debian trixie arm64 容器**（alsa-utils 1.2.14、python3-libgpiod 2.2.1、
  python3-smbus2 0.4.3、systemd 257.13、NetworkManager 1.52.1）：
  三个 unit 和 drop-in 通过 `systemd-analyze verify`；udev 规则通过
  `udevadm verify`；`udevadm test-builtin net_setup_link` 显示 `.link` 文件生效并
  保留 `eth0`；NetworkManager 读到 `wifi.scan-rand-mac-address=no`；`aplay -L`
  列出默认设备和 softvol 链路；真实 libgpiod/smbus2 的类和参数与代码用法一致；
  没有板卡设备时三个程序以退出码 1 和明确的错误信息结束。
- **原生预检**：`./build.sh -c config --check` 对现有 v0.2.9 输入通过，并列出
  8 项内核未提供的可选功能。
- **完整镜像构建**：`./build-docker.sh -c .cache/config-hardware` 从空 rootfs 构建，
  退出码 0。配置与本地 `config` 相同，只是 `BSP_DIR` 指向带相机运行时的目录并设
  `BSP_CAMERA_RUNTIME=1`。
- **镜像 rootfs（riscv64，QEMU 用户态）**：
  - `/etc/modules-load.d/t-display-k230.conf` 含五个模块；`gpio`、`i2c`、`spi` 等组存在。
  - 四个板级 unit（含相机）和 Launcher 已启用；unit 与 udev 规则在镜像自己的
    systemd/udev 下再次通过 verify。
  - `libk230mmio.so` 是 RISC-V 共享对象，`k230_mmio_write32` 反汇编为单条

## 没有验证、需要上板确认的事项

1. `lilygo-k230-power` 的 `gpio` 方式在实机上能否读到电量计和充电芯片；Python 的
   位操作速度是否被两个芯片接受。备选是 `LILYGO_K230_POWER_BUS=i2c-dev`。
2. softvol 只验证了配置能解析；控件的创建、音量效果和重启后的保存需要真实声卡。
3. 充电参数会被写入芯片：默认 704 mA / 4288 mV 是原厂值，请确认与所用电池相符。
4. 路由切换套接字在内核拒绝切换时的表现（单元测试用的是模拟的 `amixer` 失败）。
5. Wi-Fi 在 NetworkManager 下的扫描和连接；`wlan0` 命名。
6. 电源键短按是否到达 Launcher；logind 不再处理它。
7. 相机服务在加入 `sched_rt_runtime_us=-1` 后的行为。
8. Settings、Cellular、Maps、NES 读取 `/etc/default/lilygo-k230-ui` 里路径后的实际
   表现；这四个应用没有包含在本次镜像里。

键盘底板按键、触觉反馈、底板 LED、BOOT0 按键和硬件时钟在 v0.2.9 内核下不可用，
需要重建 BSP 内核，见 [硬件支持对照](../hardware-support.md) 的对应一节。
