# T-Display-K230 shared audio support — 2026-11-12

## Confirmed input state

The existing `.cache/k230-v0.2.9` BSP uses Linux 6.6.36. Its embedded
configuration and `target/lib/modules/6.6.36/modules.builtin` contain the
INNO codec, Canaan DesignWare I²S, K230 audio and K230 INNO machine drivers
as built-ins. The new preflight accepts all 288 matching RISC-V modules and
the four built-in audio driver records. `images/Image` contains the
NUL-terminated `External I2S Output Switch` control name.

The boot partition was copied to a temporary regular file and read using
`debugfs`, without mounting or changing the original image. Decompiling
`k230-canmv-rm69a10.dtb` confirms:

- `sound` is enabled and names the `K230_I2S_INNO` card.
- `canaan,external-i2s-output-default` is present.
- The amplifier pinctrl includes IO32/IO33/IO35 and shutdown IO34.
- The GPIO controller at `9140c000` matches the runtime's controller selection.

The prior November 9 Debian package manifests lack `alsa-utils`. The old
generator also lacked the vendor UI's amplifier GPIO ownership and audio
route initialization. Missing `.ko` files do not indicate missing built-in
drivers in this input.

## Changes under test

The shared board directory contains all 33 active Linux patches from
T-Display-K230 commit `c27c58c07ca5e39d15f5dcf1b7103aead29282df`, original
configuration fragments, source hashes, SDK staging, audio requirements and
Debian runtime. `canaan-gen` uses this directory for preflight, a build source
snapshot, runtime installation and provenance.

## Completed checks

- 109 canaan-gen tests passed, including BSP built-in/module evidence,
  control-marker verification, Docker input mapping and board snapshots.
- 10 SDK staging tests and 7 audio-runtime behavior tests passed.
- Native `build.sh --check` passed against the actual v0.2.9 input.
- The real Docker wrapper `build-docker.sh --check` passed with the shared
  repository mounted read-only. The retained container is
  `canaan-gen-20261112-101311-46640`; its log is in the ignored `deploy/` directory.
- A disposable Debian trixie arm64 container installed real `alsa-utils`
  1.2.14-1, `python3-libgpiod` 2.2.1-2+deb13u1 and systemd
  257.13-1~deb13u1. `systemd-analyze verify` accepted the unit; enabling it
  produced the expected service link; `aplay -L` parsed the default ALSA
  configuration; libgpiod provided the v2 request API.
- The read-only diagnostic correctly returned failure with JSON errors when
  no board devices were supplied to that container.

The container checks validate userspace integration on arm64, not RISC-V
execution or GPIO/audio hardware. No complete kernel or Debian image was
rebuilt in this validation, and no board was flashed. Real playback and
internal-route recording still require testing on T-Display-K230. External
MAX98357A output requires application PCM software volume; changing the
INNO analog volume does not adjust that output.

## Board checks after rebuilding the Debian image

```sh
sudo lilygo-k230-audio-check
systemctl status lilygo-k230-audio.service
journalctl -u lilygo-k230-audio.service -b
aplay -l
arecord -l
```

For internal headphone/capture testing, set
`LILYGO_K230_AUDIO_OUTPUT=internal` in `/etc/default/lilygo-k230-audio`,
restart the service, then perform an actual recording and playback test.
